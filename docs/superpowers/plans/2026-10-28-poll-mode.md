# Campus Crochet Poll Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve the complete storefront and add a manually switchable voting mode with separate poll photos, public results and private visitor analytics.

**Architecture:** One Next.js deployment reads the current mode from Supabase. Poll rounds, options and per-account ballots live in separate tables. Public pages switch their commerce controls to voting controls; both the order route and SQL order function reject new orders while poll mode is active. Existing payment reconciliation remains available. A first-party anonymous analytics endpoint measures approximate traffic and active time.

**Tech Stack:** Next.js 16.4.2, React 19, Supabase/Postgres/Storage, existing Google OAuth and admin password, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-28-poll-mode-design.md`

## Global constraints

- Preserve storefront commit `c8e3554` on branch `codex/full-storefront-snapshot-2026-10-28`; never remove existing ordering/payment code.
- Only `asmileis4evr@gmail.com` after Google sign-in and separate admin password may manage modes, rounds or option photos.
- No payment can start in poll mode; existing payment verification can finish.
- Browsing is public. Google sign-in is required only to save or change one multi-option ballot per round.
- New poll images are separate from product records. No candidate is published automatically.
- Visitor analytics are approximate, first-party, without stored IP/Google ID, with an opt-out; report in Asia/Kolkata time.
- Read relevant `node_modules/next/dist/docs/` before writing Next.js code.

## Review focus

- A mode switch racing order creation must never let a new order slip through after poll mode is active.
- Duplicate/replayed ballot submissions must not create extra votes; invalid option IDs must fail atomically.
- Existing gateway payments must still be verifiable after a mode switch.
- A visitor must not see bag, prices, stock or purchase buttons in poll mode, including direct URLs.
- Analytics data must not expose visitor identifiers publicly or count background time as active time.
